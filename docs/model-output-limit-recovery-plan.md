# 모델별 출력 상한과 생성 종료 복구 계획

작성일: 2026-11-02

상태: 구현 및 검증 완료. 사용자 승인한 계획과 아래 구현 기록을 함께 유지한다.
사용 방법의 현재 계약은 [모델별 출력 상한과 응답 복구](model-output-limits.md)에 정리한다.

## 목표

- Studio의 Models → Model behavior에서 모델별 출력 토큰 상한을 선택적으로 설정한다.
- 정상 종료, 출력 상한 도달, 컨텍스트 부족, 취소, 필터링, 불명확한 스트림 종료를 구분한다.
- 복구 가능한 생성은 정해진 횟수 안에서 복구하고, 잘린 응답을 성공으로 처리하지 않는다.
- 잘린 도구 인자를 실행하지 않고, 이미 끝난 도구·티켓·작업을 재실행하지 않는다.
- 부분 출력과 모든 시도의 사용량을 남겨 사용자가 결과와 비용을 이해할 수 있게 한다.

## 구현 전에 확인한 동작

| 경로 | 현재 동작과 근거 |
| --- | --- |
| 모델별 요청 설정 | `config.SamplingConfig`, `studio/settings_models.go`, `providerhost/model_groups.go`에 저장·API·후보 선택 후 적용 경로가 있다. 출력 상한 필드는 없다. |
| 일반 대화 | `agentloop/loop.go`에서 `FinishReason`을 검사하지 않고 메시지·도구를 처리한다. |
| Responses | `client/responses.go`가 `incomplete`를 오류로 반환한다. 상한·출력·추론 토큰 진단이 있지만 분기 가능한 전용 오류와 복구는 없다. |
| 빈 응답 | `agentloop/chat_recovery.go`가 같은 요청을 반복하고 마지막에 도구 이력을 제거하기도 한다. 상한 도달을 구분하지 않는다. |
| 스트리밍 | `agentloop/chat_stream.go`가 종료 사유를 모으지만 EOF만으로 반환하기도 한다. 오류 시 이미 모은 응답을 버리는 경로가 있다. |
| 작업 완료 | `client.FinishToolTurn`은 비정상 종료를 거부한다. `task_complete`의 수락과 상태 반영은 마지막 답변 수신보다 먼저 일어날 수 있다. |
| 네이티브 서브에이전트 | `subagent.Spec.Chat`과 `scoutAssistantMessage`에 공통 종료 사유 검사가 없다. 개별 도구 결과 검증은 존재한다. |
| 컨텍스트 압축 | 종료 사유 검사 없이 결과 텍스트를 체크포인트 검증에 넘긴다. |
| ACP | 일반 채팅은 부분 텍스트가 있으면 `max_tokens` 종료도 일반 결과로 반환할 수 있다. Council 참가자는 `end_turn`을 요구한다. |
| 제공자 제약 | Q가 고정한 llm-provider 버전에서 Anthropic의 미지정 상한은 65,536이다. ChatGPT 구독 어댑터는 출력 상한 지정을 거부한다. |

조사 기준은 Q가 실제 사용하는 `github.com/snowmerak/llm-provider@v0.0.0-20261014110600-2b9dafbe5452`이다.
인접 저장소의 작업 트리를 배포된 의존성으로 간주하지 않는다.

## 설정과 요청 계약

### 모델별 출력 상한

제안 저장 형태:

```yaml
model_output_limits:
  provider/model: 16384

generation_recovery:
  max_attempts: 2
```

- `model_output_limits`는 기존 모델별 설정과 같은 전역 Q config에 저장한다. 샘플링과 의미가 달라 별도 필드로 둔다.
- 미등록·화면의 빈 값은 요청 필드를 추가하지 않는다. 설정 삭제도 같은 동작이다.
- 설정값은 양의 정수다. `0`을 무제한으로 해석하지 않는다. 모델이 알려준 최대 출력량을 넘으면 저장을 거부한다. 미확인 메타데이터는 알려진 한도로 가장하지 않고 제공자 검증 결과를 전달한다.
- 요청에 별도 상한이 있으면 모델별 설정과 요청값 중 작은 값을 적용한다. 모델 메타데이터는 검증용 능력 정보이고 사용자 설정과 분리한다.
- `group/*`에는 직접 저장하지 않는다. 폴백 후보가 정해진 뒤 해당 실제 모델에 적용하여 후보 간 설정이 섞이지 않게 한다.
- Gateway의 기존 설정 재조회 경로를 활용한다. 같은 논리 생성의 복구 시도는 최초 실효 상한과 정책을 유지하며, 설정 변경은 다음 논리 생성부터 적용한다.
- Studio 설정 API·타입·내보내기/가져오기에 포함한다. 기존 설정에 필드가 없으면 지금처럼 상한 미지정이다.
- 이 상한은 한 API 요청의 생성량이다. 입력 컨텍스트 크기나 전체 에이전트 작업 예산을 대체하지 않는다.

### 제공자 적용

| 경로 | 계획 |
| --- | --- |
| Chat Completions | 일반 공통 경로는 `max_completion_tokens`를 사용하고 충돌하는 `max_tokens`와 중복 전송하지 않는다. `max_tokens`만 지원하는 연결은 명시적 제공자 설정으로 선택한다. 실패를 근거로 임의 필드 전환을 반복하지 않는다. |
| Responses | `max_output_tokens`로 적용한다. |
| Anthropic 어댑터 | 기존 typed 변환을 재사용해 최종 `max_tokens`로 적용한다. |
| ChatGPT 구독 | 현재 어댑터의 미지원 상태를 화면/API에 표시하고 상한 저장·적용을 거부한다. |
| ACP | 현재 Q의 공통 출력 상한을 강제로 전달하지 않는다. 서버가 제공하는 설정을 연동하는 작업은 별도 범위다. 종료 사유 검사와 부분 결과 보존은 이번 범위에 포함한다. |

독립 `app.RunAgentLoop` 사용자는 관리 Gateway를 통하지 않을 수 있다. 클라이언트가 제공하는 명시적 상한도 같은 종료 검사·복구 정책을 적용받도록 공통 계약을 둔다.
관리 Gateway는 실제 후보의 실효 상한과 지원 여부를 Q 클라이언트에 전달해야 한다. 내부 응답 메타데이터를 재사용하거나 추가하여 복구 요청마다 상한이 달라지는 일을 막고, 내부 정보는 외부 제공자 요청으로 유출하지 않는다.

### 복구 설정

- `generation_recovery.max_attempts`는 **원 요청 이후 추가 복구 횟수**다. 제안 기본값은 2, 명시적 0은 자동 복구 비활성화다. 생략과 0을 저장·API에서 구분한다.
- 출력 상한·빈 응답·미완료 생성 복구는 하나의 논리 생성 ID와 카운터를 공유한다. 기존 빈 응답 복구 안에 새 복구 루프를 중첩하지 않는다.
- 429/5xx 등 기존 전송 재시도는 별도 정책이다. 의미적 복구 횟수가 전체 HTTP 전송 횟수나 작업 전체 비용 상한인 것처럼 표시하지 않는다.
- 복구는 사용자 지정 출력 상한·reasoning effort·모델을 자동 변경하지 않는다. 한 요청의 상한을 지켜도 여러 요청의 합산 비용은 늘 수 있음을 설정 도움말에 표시한다.

## 종료 결과와 공통 실행 경계

`client`에 원래 종료 사유를 보존하는 공통 판정과 구조화된 미완료 오류를 둔다. 오류에는 사유, 부분 응답, 사용량, 실효 상한, 모델, 복구 횟수와 완료된 호출 정보를 실을 수 있어야 한다.

| 분류 | 처리 |
| --- | --- |
| 정상 텍스트 종료 | 결과를 수락한다. |
| 정상 도구 호출 종료 | 전체 호출과 인자를 검증한 뒤 기존 실행 경로로 넘긴다. |
| 출력 상한 도달 | 아래 복구 표를 적용한다. |
| 컨텍스트 부족 | 보존된 정상 이력으로 기존 압축이 가능한 경우에만 압축 후 제한적으로 재시도한다. |
| 취소·기한 만료 | 즉시 멈추고 부분 결과를 보존한다. |
| 콘텐츠 필터·거부 | 해당 결과와 사유를 표시하며 자동 재요청하지 않는다. |
| 알 수 없는 종료·스트림 중단 | 완료로 단정하지 않는다. 실제 순수 모델 호출이고 텍스트만 안전하게 이어받을 수 있을 때만 제한적으로 복구한다. |

- OpenAI/Anthropic의 `length`, Responses의 `incomplete_details`, ACP의 `stopReason`를 원래 값과 함께 분류한다.
- `max_output_tokens`라는 사유만으로 출력 예산 부족과 컨텍스트 여유 부족을 단정하지 않는다. 사용량·입력 추정·모델 메타데이터를 함께 확인하고 근거가 부족하면 진단을 남긴다.
- 종료 사유가 없는 호환 서버 응답의 허용 조건은 명시적 호환 정책으로 정의한다. `EOF`나 HTTP 200만을 모든 경로의 정상 종료 근거로 사용하지 않는다.
- 판정은 텍스트 수락·체크포인트 적용·도구 실행 **이전**에 수행한다. Responses 오류도 부분 결과와 사용량을 잃지 않는 구조로 변환한다.
- `client`의 공통 판정·복구 도우미를 기존 `agentloop` 및 네이티브 생성 경계에서 재사용한다. 새로운 에이전트 실행 루프는 만들지 않는다.

## 결과별 복구

| 상황 | 자동 복구 제안 | 성공 조건과 중단 조건 |
| --- | --- | --- |
| 일반 텍스트가 출력 상한으로 중단 | 기존 부분 텍스트를 유지하고 다음 조각을 요청한다. 복구 호출에서는 도구를 비활성화하고 남은 답변을 짧게 이어 쓰도록 요청한다. | 정상 종료하면 같은 assistant 턴의 연속 결과로 수락한다. 추가 진전이 없거나 횟수를 소진하면 미완료로 남긴다. |
| 추론만 있고 사용자에게 줄 내용이 없음 | 같은 예산의 동일 요청을 반복하지 않는다. | 부분 사용량과 상한을 표시하고 상한·effort 조정이 필요함을 안내한다. |
| 도구 호출 또는 혼합 출력이 잘림 | 해당 생성의 모든 도구 호출을 실행하지 않는다. 부작용 없는 모델 호출임이 확인된 경로에서만 원래 정상 이력으로 한 번 다시 생성한다. 작은 인자·아티팩트 참조를 사용하도록 안내한다. | 정상 종료와 전체 인자 검증 후 새 결과만 실행한다. 모델을 재호출하기 전에 실행된 호출이 없어야 한다. 부분 인자를 이어 붙여 호출을 복원하지 않는다. |
| 구조화 결과·압축 체크포인트가 잘림 | 같은 정상 원문으로 한 번 전체 재생성하되 더 간결한 결과를 요구한다. | 종료 사유와 기존 스키마 검증이 모두 통과해야 적용한다. 실패 시 원래 이력·체크포인트를 유지한다. JSON 문자열 조각을 합쳐 적용하지 않는다. |
| 이미 수락한 `task_complete` 이후 마지막 답변만 잘림 | 도구를 끈 마지막 답변만 짧게 복구한다. | 기존 완료 결과를 유지하고 `task_complete`, 티켓 상태 변경, 파일 변경을 반복하지 않는다. |
| 컨텍스트 여유 부족 | 정상 이력에 기존 압축 경로를 한 번 적용할 수 있는지 확인한 뒤 재요청한다. | 압축 자체의 완료와 유효성이 먼저 확인돼야 한다. 불가능하면 원문을 보존하고 종료한다. |
| ACP 또는 도구를 자체 실행하는 원격 에이전트 | 부분 출력·종료 사유를 보존하고 미완료로 표시한다. | 이번 범위에서는 자동 프롬프트 재전송·세션 초기화·다른 에이전트 재할당을 하지 않는다. 순수 모델 응답과 같은 재실행 안전성을 가정하지 않는다. |

- 표의 한 번 재생성도 공통 추가 복구 횟수 안에서 소비한다. 압축 실패를 다시 압축 복구로 보내는 재귀를 허용하지 않는다.
- 문장 조각의 자연어 중복 여부는 완벽하게 보장할 수 없다. 문자열 접미사 추측으로 내용을 삭제하지 않고 시도별 조각을 보존한다.
- 구조화 출력이나 도구 호출에는 자연어 이어쓰기 병합을 적용하지 않는다.
- 순수 모델 경로와 서버가 도구를 실행하는 경로를 실제 연결 설정·런타임 정보로 구분한다. 정보가 없는 주입 클라이언트의 자동 재생성은 명시적 opt-in을 요구한다.
- 자동으로 다른 모델에 넘기거나 설정 상한을 올리지 않는다. 기존 전송 실패 폴백과 생성 미완료 복구를 구분한다.

## 스트리밍·사용량·저장

- 하나의 사용자 턴 아래 생성 시도 ID, 순번, 종료 사유, 복구 유형을 기록한다. 복구 중이라는 상태를 TUI·Studio에서 보여준다.
- 일반 텍스트 이어받기와 전체 재생성을 구분하는 이벤트를 둔다. 현재 `AgentStreamDelta.Start`가 버퍼를 비우는 동작을 그대로 재사용해 이전 부분 출력을 지우지 않는다.
- 부분 메시지·잘린 툴 인자·실패한 체크포인트는 감사 이력에 남기고 실행 가능한 정상 대화 이력에 섞지 않는다. 정상화된 결과만 기존 실행·메모리 경계로 전달한다.
- 제공자가 보고한 모든 시도의 입력·출력·추론·캐시 사용량을 시도별로 기록하고 턴 합계에 포함한다. 최종 시도의 사용량만 남기거나 기존 usage recorder와 중복 계산하지 않는다. 미보고 사용량은 미확인으로 남긴다.
- 실패·취소 시 부분 결과를 지우지 않고 미완료 상태와 다음 조치를 표시한다. Studio 새로고침·로그 재생 후에도 같은 상태가 보이게 한다.
- 복구 요청에 들어가는 부분 텍스트·네이티브 Responses 출력·대화 ID의 처리 규칙을 분리한다. 잘린 함수 호출과 도구 결과 짝을 정상 이력처럼 재생하지 않는다.
- 재시작 시 감사 로그만을 근거로 원격 에이전트나 미완료 도구를 자동 재실행하지 않는다. 기존 세션·티켓 복구 계약을 보존한다.

## 구현 순서

1. **종료 검사와 부분 결과 보존:** 구조화된 오류·사용량·부분 응답 계약을 만들고 Chat/Responses/ACP의 현재 판정을 통일한다. 우선 잘린 결과의 성공 처리·도구 실행을 막는다.
2. **모델별 상한 저장과 전송:** config 검증, Studio 조회·수정·전송, Gateway 후보별 실효값 적용, 제공자 지원 정보와 API별 필드 변환을 연결한다. 설정 상한은 모델 메타데이터와 분리한다.
3. **네이티브 제한 복구:** 텍스트 이어받기, 도구·구조화 결과 전체 재생성, 마지막 답변 복구를 공통 추가 시도 예산으로 연결한다. 기존 빈 응답 복구와 중복되지 않게 한다.
4. **메모리와 실행 수명:** 압축 성공 판정·원문 보존, `task_complete` 이후 복구, 티켓·MR 중복 방지를 확인한다. ACP에는 미완료 판정과 표시를 적용한다.
5. **화면과 이력:** Model behavior 입력, 복구 설정, 스트리밍 상태·부분 결과·새로고침·사용량 표시와 도움말을 완성한다.
6. **통합 검증:** 아래 수락 기준을 통과시키고 사용자 문서와 이 계획의 구현 상태를 갱신한다.

예상 영향 영역: `config`, `client`, `providerhost`, `agentloop`, `subagent`, `app`의 이벤트/ACP 연결, Studio 설정 API·전송·화면·실행 로그. 제공자별 기존 변환으로 충족하지 못하는 사항만 llm-provider에서 수정하고, 필요한 경우 새 버전을 명시적으로 고정한다.
Library 원본 스키마나 새 작업 큐 추가는 필요하지 않다.

## 수락 기준과 검증

### 설정과 전달

- 빈 값·설정 제거 시 요청에 새 상한이 남지 않는다. 양수 검증, 미지원 연결, 모델 메타데이터 초과, 명시적 0의 거부를 검사한다.
- Chat/Responses/Anthropic 최종 요청의 필드와 값이 맞고 동의어 필드가 충돌하지 않는다.
- 사용자 요청 상한과 모델별 상한의 작은 값이 적용된다. 후보 A에서 B로 폴백하면 B 설정을 사용한다.
- 동작 중 설정 변경이 현재 복구 시도의 상한을 바꾸지 않으며 다음 논리 생성에 반영된다.
- 저장·재시작·내보내기/가져오기로 설정이 유지되고, 기존 설정에 필드가 없을 때 기존 동작을 유지한다.

### 종료와 복구

- Chat `length`, Responses `incomplete`, ACP `max_tokens`를 성공으로 처리하지 않는다. 정상 `stop`/`tool_calls`/`end_turn`은 기존 흐름을 유지한다.
- 텍스트 이어받기는 상한을 지키며 복구하고 스트리밍 이전 조각·최종 결과·새로고침 내용이 보존된다.
- 잘린 호출이 일부 유효한 JSON을 포함해도 해당 생성의 도구는 실행되지 않는다. 성공한 새 생성의 호출만 한 번 실행한다.
- 구조화 결과·압축 복구 실패 시 기존 정상 체크포인트와 원문이 그대로 남는다.
- 이미 실행한 파일 변경·`task_complete`·티켓 완료·MR 처리는 마지막 답변 복구 때문에 다시 실행되지 않는다.
- 추론만 소진한 응답, 진전 없는 반복, 횟수 소진, 필터링·거부, 취소·기한 만료가 각각 정해진 사유로 종료된다.
- 종료 이벤트가 없는 EOF와 도구 조각이 섞인 중단 스트림을 정상 완료로 오인하지 않는다.
- 기존 빈 응답·전송 재시도와 의미적 복구를 중첩해 무제한 반복하지 않는다. 자동 모델 변경이나 상한 증액이 없다.
- ACP 미완료 뒤 프롬프트가 자동 재전송되지 않고, 세션 ID·부분 결과·종료 사유가 보존된다.
- 모든 보고된 시도의 사용량은 누락·중복 없이 집계한다. 부분 응답이 있는 오류도 usage recorder에 남는다.

검증 계층은 config/API 단위 검사, 가짜 모델 HTTP/SSE를 통한 실제 Gateway·SessionHost 통합 검사, Studio Playwright 설정·복구·로그 재생 시나리오를 사용한다. 실제 유료 모델 요청이나 사용자 실행 중 프로세스 재시작은 이 계획 검증에 포함하지 않는다.

## 구현 기록

- 모델별 상한·Chat 필드·종료 사유 생략 호환·추가 복구 횟수를 config와 Studio API/UI/설정 전송에 추가했다. 생략과 명시적 0을 구분한다.
- Gateway가 실제 폴백 후보의 실효 모델·상한·effort·호환 정책을 응답 메타데이터로 전달한다. 같은 Gateway 수명 안에서 서명된 스냅샷으로 복구 설정을 유지하며 외부 제공자에는 내부 헤더를 전달하지 않는다.
- 공통 생성 판정과 `IncompleteGeneration` 오류, 제한적인 텍스트 이어받기/전체 재생성, 컨텍스트 부족 후 기존 압축 경로를 연결했다. 빈 응답과 출력 복구 카운터는 공유한다.
- 부분 출력·잘린 호출·사용량을 감사 이벤트로 보존하고, 실패·취소한 부분 텍스트를 정상 모델 메모리와 분리했다. ACP는 자동 재전송 없이 미완료로 표시한다.
- 기존 주입 클라이언트의 finish reason 생략 호환은 유지한다. 표준 HTTP 클라이언트는 기본적으로 종료 사유를 요구하고, 주입 클라이언트의 부분 재생성은 명시적 `SafeReplay` opt-in으로 제한한다.
- 전체 Go 검사 44개 패키지가 통과했고, 취소 부분 보존·거부 응답·스냅샷 effort 고정·Responses의 부분 사용량 보존 추가 회귀 검사도 통과했다.
- Playwright 3개 시나리오 통과: 설정 저장/초기화/0/모바일, 실제 잘린 스트림의 같은 턴 복구와 새로고침 재생, 기존 샘플링 저장/초기화 회귀. Browser 플러그인이 없어 저장소 Playwright와 설치된 Edge를 사용했다.
- 정적 검사(golangci-lint 2.15.0 기본 검사), `go vet`, 프런트엔드 검사/빌드, 버전 모듈 설치 검사, `govulncheck`의 호출 경로 취약점 0건을 확인했다. 최신 소스로 실행 파일을 다시 빌드했다. 사용자 Studio 프로세스는 재시작하지 않았다.
