# 프로젝트 관리와 실행 설정 계획

작성일: 2026-10-30

## 범위와 계약

- Studio Project를 기존 workspace UUID 단위로 유지하고, 별도 Projects 화면에서 목록·생성·수정·보관을 제공한다.
- Sessions의 프로젝트 생성 아이콘과 편집 대화상자를 제거한다. 프로젝트별 세션 탐색은 유지하고 설정 바로가지는 Projects로 연결한다.
- Tickets의 멤버 관리 편집 UI를 Projects로 옮긴다. 담당자·실행 상태와 프로젝트 설정 바로가지는 유지한다.
- 기존 네이티브·ACP 프로필을 참조하는 참여 멤버를 관리한다. 프로필 정의와 연결 정보는 기존 설정을 재사용한다.
- Library에 신규 프로젝트의 기본 멤버 세트를 저장한다. 기본 세트는 내장·전역 프로필 ID 목록이며 생성 시 선택 내용을 변경할 수 있다. 기존 프로젝트에는 소급 적용하지 않는다.
- 기본 멤버의 정의·실행 디렉터리는 프로젝트의 첫 디렉터리이며, 생성 후 개별 변경할 수 있다. 프로젝트와 초기 멤버는 하나의 source 트랜잭션으로 생성한다.
- 프로젝트별 동시 티켓 수와 작업 내부 위임 병렬 수를 구분한다. 0은 전역 설정 상속이며 실효값은 전역 상한을 넘지 않는다.
- 티켓 예약은 Library에서 전역·프로젝트 실행 수를 함께 검사한다. reserved/running만 집계하고 대기·검토는 제외한다.
- 내부 위임 제한은 Q가 실행하는 동일 부모 작업의 직계 하위 위임에 적용한다. 하위 작업의 별도 위임은 자신의 부모 범위에서 제한하여 부모가 슬롯을 점유한 채 자식을 기다리는 교착을 피한다. ACP 자체의 내부 에이전트 병렬성은 ACP가 관리하며 Q의 티켓 실행 제한은 동일하게 적용한다.
- 설정은 다음 예약·위임부터 다시 읽는다. 제한 하향이나 멤버 비활성화가 이미 실행 중인 작업을 강제 종료하지 않는다.
- 기존 프로젝트는 멤버·이력·Coordinator/Integrator ID와 모델 선택을 보존하고 새 제한은 전역값을 상속한다.

## 구현 순서

1. **저장/API**: Library source에 프로젝트 실행 제한과 기본 멤버 세트 추가, 스키마 마이그레이션, 원자적 초기 멤버 등록, 기존 갱신 요청의 생략 필드 보존.
2. **실행**: 티켓 예약 시 프로젝트 상한 강제, Q 위임 시 부모별 병렬 제한 및 설정 재조회, 실행 중 작업 보존.
3. **Studio API**: 기본 세트 읽기·수정, 프로젝트 생성 전 프로필 검증, 프로젝트 멤버 설정과 기존 디렉터리 검증 재사용.
4. **화면**: Projects 목록·설정·기본 세트, 생성 시 기본 멤버 선택, 기본·서브에이전트·실행 섹션. Sessions/Tickets에서는 설정 바로가기만 제공.
5. **검증**: source 원자성·기존 데이터 보존·상한과 상속·실행 중 제한 변경·취소 가능한 위임 대기·실제 브라우저 생성/편집/멤버/기본값 흐름·모바일 배치 확인.

## 검증 기준

- 기본 세트가 신규 프로젝트의 첫 멤버 조회부터 보이며, 잘못된 초기 멤버로 생성하면 프로젝트도 남지 않는다.
- 기본 세트 수정이 기존 프로젝트 멤버를 바꾸지 않는다.
- 프로젝트 설정 저장 후 새 티켓·위임의 제한이 반영되고, 이미 실행 중인 작업은 유지된다.
- 다른 프로젝트의 여유 작업은 프로젝트 상한에 의해 차단되지 않으며 전역 상한은 지켜진다.
- Sessions의 생성 아이콘과 Tickets의 멤버 편집 UI가 제거되고 모든 바로가기가 같은 Projects 화면으로 연결된다.
- 기존 보호 세션, 이슈·티켓과 프로필 데이터가 유지된다.

## 진행 상태

구현 완료.

- Projects: 목록·생성·이름/디렉터리 수정·보관, 기본 세트, 참여 멤버 바인딩과 활성화, 실행 제한. 모바일에서는 프로젝트 선택기를 사용한다.
- Sessions의 프로젝트 생성·편집 대화상자를 제거하고 프로젝트 설정 아이콘으로 연결했다. Issues/Tickets에서도 같은 설정 화면으로 이동한다.
- Library schema 7 / protocol 11. 기본 세트는 revision을 검사하여 저장한다. 생성 요청에서 `initial_members` 생략은 저장된 기본 세트, 명시적 빈 배열은 멤버 없음이다. 갱신 시 `limits` 생략은 기존 제한을 보존한다.
- 명시적 `global/name`과 `workspace/name`은 이름이 같아도 각각 선택할 수 있다. 초기 선택은 실제 프로필과 활성 ACP 연결을 검사한다. 기존 멤버/보호 세션/이력의 ID를 바꾸지 않는다.
- 프로젝트 설정은 Library, 전역 상한은 기존 config의 `agents.max_parallel`이 원본이다. 티켓은 기존 2초 스캔 후 source 예약 트랜잭션에서 검사한다. 한도에 도달한 프로젝트는 호스트 접수 슬롯을 잡기 전에 제외하여 다른 프로젝트의 접수를 막지 않는다. Q 위임은 새 호출에서 다시 읽으며 슬롯 대기 중에도 최대 100ms 간격으로 재조회한다. 실행 중 호출은 제한 하향으로 취소하지 않는다.
- ACP 내부 병렬성과 프로필의 기존 도구·위임 정책은 각 기존 실행 경로가 관리한다.

검증:

- `go test ./workitems ./library ./coordinator ./app ./studio -count=1 -timeout=180s` 통과.
- 추가 source/API 테스트: 기본 세트 스냅샷과 stale revision, 빈 선택, 잘못된 멤버의 원자적 롤백, schema 6 마이그레이션, 생략한 제한 보존, 프로젝트/전역 예약 상한과 제한 변경. 한도가 찬 프로젝트의 대기열이 다른 프로젝트를 막지 않는 스케줄러 회귀 테스트도 통과했다.
- Q 위임 테스트: 부모별 슬롯 격리, 취소 가능한 대기, 상한 변경과 config/Library 재조회.
- `go vet` 및 golangci-lint 2.15.0 기본 검사(errcheck, govet, ineffassign, staticcheck, unused) 통과. 프런트엔드 `check` 오류/경고 0, `build` 통과.
- Playwright 6개 시나리오 통과: 프로젝트 생성·디렉터리 탐색·기본 세트·멤버·상한·보관, 티켓 자동 접수, 프로젝트별 세션 등록, 기존 이슈 본문/검색, 보호 Coordinator/Integrator 세션. 390/1440px와 글자 배율 1/1.3에서 가로 넘침과 선택 상자/입력의 세로 잘림 없음.
- `bin/q.exe` 빌드. 현재 실행 중인 사용자 Studio는 재시작하지 않았다. 새 바이너리로 Studio/Library를 다시 시작하면 새 화면과 프로토콜이 적용된다.
