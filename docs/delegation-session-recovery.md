# 중첩 delegate 세션과 재귀 복구

상태: 구현 및 파일 기반 복구 테스트 완료

작성일: 2026-09-26

## 목적

일반 `delegate` 호출이 진행 중에 Q가 종료되어도 호출 트리와 각 에이전트의 대화를 복원한다. 부모 세션은 자식 세션을 가리키는 북마크를 저장한다. 재시작하면 북마크를 따라 가장 깊은 자식부터 복구하고, 자식의 결과를 원래 `delegate` 도구 호출의 결과로 부모에게 돌려주며 올라온다.

이 문서는 [일반 delegated subagents](delegated-subagents.md)의 세션 복구 형식과 동작을 설명한다. `/plan`의 승인된 실행은 기존 [ExecutionCheckpoint](../subagent/execute_loop.go)를 계속 사용한다.

## 구현 기준선

- [`workspace.Session`](../workspace/session.go)은 기본 대화의 `transcript`, `context`, Responses 재생 항목과 캐시 친화성 키를 저장한다. 세션 파일은 임시 파일을 동기화한 뒤 교체한다.
- [`GeneralRunner`](../subagent/delegation.go)는 모델 메시지와 도구 결과마다 체크포인트를 요청하고 저장된 `transcript`와 `context`에서 재개한다. [`delegationDispatcher`](../app/delegation.go)는 부모 호출의 북마크와 자식 세션을 연결한다.
- [`subagent.Lifecycle`](../subagent/lifecycle.go)은 작업과 메시지를 검색 아카이브에 기록할 수 있다. 아카이브 writer의 `Append`는 비동기 큐 적재이므로, 돌발 종료 후 재개의 기준 파일로 사용하지 않는다.
- 기본 대화 복원은 미완료 `delegate` 호출을 보존하고 별도 복구 작업으로 자식을 먼저 처리한다. 미완료 일반 도구 호출은 `unknown` 결과로 닫는다.

## 세션 트리

각 `delegate` 호출은 부모 세션 아래 고유한 자식 세션 하나를 가진다. 자식이 다시 위임하면 같은 구조를 반복한다. 자식은 최상위 `/sessions` 목록에 독립 대화로 나타나지 않는다.

```text
.q/sessions/<root-session-id>/
  session.json                 # 기존 공통 대화 형식
  delegations.json             # 이 세션이 호출한 자식 북마크
  delegates/<invocation-id>/
    session.json               # 자식 자신의 공통 대화 형식
    delegation-state.json      # 자식 실행 단계와 최종 결과
    delegations.json           # 손자 북마크; 없을 수 있음
    delegates/<invocation-id>/...
```

구형 `.q/session.json` Store에서도 같은 원칙으로 `.q/delegations.json`과 `.q/delegates/`를 사용한다. 새 북마크 ID는 Q가 생성하고, 읽을 때 경로 구성 요소와 심볼릭 링크를 검증한다. 부모 세션의 lock이 하위 트리의 단일 실행자를 보호한다.

`delegations.json`의 북마크는 부모 `run_id`, 자식 `invocation_id`, 부모 `transcript`의 메시지 인덱스와 그 메시지 안의 도구 인덱스, 원본 `call_id`, 에이전트 ID, 정확한 요청 문구, 생성 시각을 가진다. 두 인덱스로 같은 `call_id`가 반복되어도 호출을 구분한다. 북마크를 재시도할 때 새 자식을 만들지 않는다. 경로를 열 때는 부모 디렉터리 밖으로 벗어나는 경로와 심볼릭 링크를 거절한다.

자식 `session.json`은 기본 세션 v2와 같은 메시지 형식을 사용한다. `transcript`는 실제 호출 이력, `context`는 다음 모델 요청에 사용할 문맥이다. Responses `response_replay`와 자식의 선택 모델·후보·API 종류·대화 키를 담는 `response_affinity`도 해당 자식에게만 속한다. `delegation-state.json`에는 라운드와 알림 횟수, `task_start` 상태, 선택한 에이전트·모델·API 종류, 실행 중 도구 호출, 확인불가 도구 호출, 완료된 결과를 둔다. 모델 대화 본문은 중복 저장하지 않는다. 세션 파일이 상태 파일보다 앞서 저장된 채 종료되면 세션의 호출 이력과 모델 정보를 기준으로 상태를 보정한다. 복구 때 저장된 모델·에이전트 설정 또는 API 종류를 사용할 수 없으면 다른 모델로 조용히 전환하지 않고 해당 자식을 `blocked`로 반환한다.

## 기록 순서

1. 부모가 만든 `delegate` 도구 호출을 부모 `session.json`에 저장한다.
2. 부모 `delegations.json`에 북마크를 **동기적으로** 저장한다. 북마크에는 자식 세션이 아직 없을 때 재생성할 수 있도록 요청을 포함한다.
3. 북마크의 ID로 자식 세션과 초기 요청을 저장한 뒤 자식 실행을 시작한다.
4. 자식은 모델 메시지, 도구 호출, 도구 결과 및 실행 단계가 확정될 때마다 자기 세션과 상태를 저장한다. 도구를 실행하기 전에는 해당 호출을 `running_call`로 기록한다.
5. 자식의 최종 `TaskResult` 또는 외부 ACP 결과를 자식 상태에 먼저 저장한다. 그다음 부모의 동일한 `call_id`에 도구 결과를 기록하고 부모의 다음 모델 요청을 시작한다.

북마크, 세션, 상태 파일은 각각 임시 파일 동기화 후 교체한다. 파일 간 단일 트랜잭션은 요구하지 않는다. 복구는 북마크와 실제 자식 파일 중 이미 기록된 부분을 확인해 빠진 단계를 멱등적으로 채운다. 쓰기 실패 시 새 도구 실행으로 진행하지 않는다. 검색 아카이브는 조회용 기록이며 이 순서의 성공 여부를 결정하지 않는다.

## 재귀 복구

복구는 부모 세션의 미완료 `delegate` 호출마다 다음 순서를 적용한다. 논리적 순서는 깊이 우선이다. TUI는 시작 후 별도 명령에서 복구하고, 자식의 진행과 추적 이벤트를 표시한 뒤 완료 이벤트를 받으면 부모 모델 턴을 이어간다. ACP는 다음 요청을 처리하기 전에 복구된 턴을 먼저 마치며 복구 중에도 같은 이벤트를 전달한다. 각 이벤트의 자식 `task_id`와 `parent_id`는 호출 트리를 구분한다.

1. 부모에 해당 도구 호출 순번과 `call_id`의 결과가 이미 있으면 자식을 다시 실행하지 않는다.
2. 북마크가 없고 부모에 저장된 `delegate` 호출만 있으면, 그 호출 인자로 북마크와 자식 초기 세션을 만든다. 아직 자식을 시작하지 않은 지점이므로 안전하다.
3. 북마크는 있고 자식 세션이 아직 시작되지 않았다면 북마크의 요청으로 같은 ID의 초기 세션을 만든다. 이미 진행된 상태 기록은 있는데 세션이 없거나 기록끼리 모순되면 `blocked` 결과를 저장한다.
4. 자식의 북마크를 먼저 내려가서 복구한다. 완료된 손자의 저장 결과는 자식의 해당 도구 결과로 기록한다.
5. 자식의 미완료 일반 도구 호출을 아래 규칙대로 정리한 뒤, 저장된 문맥과 실행 단계에서 자식 에이전트를 계속 진행한다.
6. 자식의 최종 결과가 저장되면 부모의 원래 도구 호출 결과로 기록하고 한 단계 올라간다.

자식 결과가 저장된 뒤 부모 결과를 쓰기 전에 종료되더라도 저장된 자식 결과를 재사용한다. 부모 결과가 이미 저장되었다면 자식이 다시 실행되지 않는다. 도구 결과가 자식 `session.json`에 있고 상태 파일만 `running`이면 이미 저장된 결과를 우선한다. 부모 결과가 디스크에 기록되고 UI에 반영되기 전에 끊겨도 다음 복구가 이를 다시 읽는다. 저장된 북마크도 총 호출 수 제한에 포함한다.

## 결과를 확인할 수 없는 도구 호출

`running`으로 저장된 일반 도구 호출에 결과가 없다면 실제 도구가 실행되었는지 알 수 없다. 이를 성공·실패·취소로 바꾸지 않고 **`unknown`(확인불가)** 상태로 저장한다. 해당 에이전트에게는 같은 `call_id`의 도구 결과를 `IsError: true`와 명시적인 `status: unknown` 내용으로 한 번 반환한다. 이 상태가 저장되기 전에는 다음 모델 요청을 시작하지 않는다.

에이전트는 이 결과를 보고 확인 작업을 하거나 `blocked` 결과를 낼 수 있다. Q의 복구 코드가 원래 도구를 자동 재실행하지는 않는다. `task_complete`가 없는데 자식 작업을 성공으로 표시하지도 않는다. 외부 ACP 자식의 내부 상태를 다시 열 수 없으므로 진행 중이던 `delegate` 호출 자체를 `unknown`으로 기록해 부모에게 반환한다. 외부 ACP 세션의 내부 재개는 현재 지원하지 않는다.

`unknown`은 **도구 실행의 결과 상태**다. 자식의 `TaskResult`에 있는 `succeeded`·`blocked`와 혼동하지 않는다. 검색 아카이브에도 별도 상태로 남겨 사후 확인이 가능해야 한다.

예를 들어 `root → executor → coder` 위임 중 `coder`의 `run_command`에서 종료되었다면, 복구는 `coder` 세션에 그 명령의 `unknown` 결과를 기록한다. `coder`가 그 결과를 보고 확인하거나 `blocked`를 반환하면, 저장된 결과가 `executor`의 `delegate` 결과가 되고 마지막으로 `root`에 전달된다. 복구 코드가 `run_command`를 다시 실행하지는 않는다.

## 보존과 정리

활성 부모 세션의 하위 세션과 북마크는 복구가 끝날 때까지 보존한다. 완료된 자식도 부모 세션이 존재하는 동안 조회할 수 있게 두며, 부모 세션을 삭제하면 하위 트리를 함께 정리한다. `/clear`로 부모의 `run_id`가 바뀌면 이전 실행의 북마크를 재개하지 않는다. 자식 세션은 부모의 문맥 크기를 늘리지 않는다. 부모에게는 저장된 최종 도구 결과만 전달한다. 장기 아카이브와 별도의 자동 보존 기간은 이번 설계에서 정하지 않는다.

## 구현 경계와 검증

- `workspace`: 부모 아래 자식 Store 경로, 북마크·실행 상태의 버전 검증과 원자적 저장, 트리 삭제를 담당한다.
- `subagent.GeneralRunner`: 새 실행과 저장 문맥에서의 재개를 같은 루프로 처리하고, 각 메시지·도구 경계에 체크포인트를 요청한다.
- `app.delegationDispatcher`: 부모 호출과 자식 세션을 연결하고, 재귀 복구로 얻은 결과를 원래 `call_id`에 반환한다. 기본 대화의 미완료 호출 정리는 `delegate` 북마크 복구 후 수행한다.
- TUI와 ACP: 같은 복구 로직을 호출한다. TUI는 별도 명령으로 실행하고 늦게 도착한 취소 결과를 무시한다. ACP는 첫 후속 요청 전에 복구한다. `/plan`의 별도 체크포인트는 유지한다.

검증은 부모→자식→손자 트리를 실제 파일에 저장하고 새 실행 상태에서 복원한다. [앱 복구 테스트](../app/delegation_recovery_test.go)는 북마크만 저장된 경우, 자식 상태는 있고 세션이 없는 경우, 자식 완료 후 부모 결과 저장 전, 일반 도구 실행 중, 상태 파일보다 앞선 세션 결과, 손자 완료 후 부모 재개, 외부 ACP의 확인불가, 반복된 `call_id`, 모델·API 종류·에이전트 설정 변경, Responses 재생 항목과 캐시 친화성 키, 호출 수 제한, 터미널 응답 저장 후 종료, 취소 후 늦게 도착한 결과와 재시도를 다룬다. [하위 실행 테스트](../subagent/delegation_recovery_test.go)는 체크포인트 실패 시 도구가 실행되지 않음을 확인한다. [저장소 테스트](../workspace/delegation_test.go)는 경로 검증, 북마크 충돌, 손상된 상태, 세션 트리 삭제를 확인한다.
