# 서브에이전트 실행과 티켓 할당

Q의 서브에이전트 실행은 Studio 프로젝트의 티켓을 통해 요청한다.

1. Projects에서 기존 네이티브/ACP 프로필을 참여 멤버로 등록한다.
2. `workspace_members`로 프로젝트에 참여한 후보를 조회한다.
3. `ticket_create`로 목적, 내용, 수락 기준과 실행 모드(`report` 또는 `git`)를 명시해 티켓을 발행한다. 필요한 경우 참여 멤버 ID를 요청 담당자로 지정한다.
4. 발행 성공은 Library의 내구성 있는 큐 접수다. System One이 적절한 참여 멤버를 선택하고 워커를 비동기로 실행한다.
5. 결과와 변경 요청은 해당 프로젝트 Integrator가 티켓 리뷰 경로로 처리한다. 피드백과 재실행도 티켓 상태 및 시도 기록을 사용한다.

메인 루프와 내장 네이티브 작업자는 추가 작업에 티켓 도구를 사용한다. 티켓 접수 응답을 실행 완료로 해석하거나 다른 작업자를 동기적으로 기다리지 않는다. 현재 프로젝트가 없다면 먼저 프로젝트 선택을 요청한다. 커스텀 프로필은 기존 도구 허용 목록을 유지하므로 티켓을 발행하려면 `ticket_create`가 허용되어 있어야 한다.

## 제거된 직접 실행 계약

- `delegate_list`, `delegate`는 모델 도구 목록에서 제거했다. 오래된 대화나 직접 런타임 호출이 해당 이름을 요청해도 새 작업을 실행하지 않고 티켓 사용을 안내한다.
- `/subagent <name> <request>` 직접 실행과 예전 위임 세션의 후속 실행도 중단했다. `/subagents` 프로필/연결 설정은 유지한다.
- 내장 작업자 프롬프트의 직접 위임 지침을 티켓 발행 지침으로 교체했다. 새 세션에는 직접 자식 MR 도구를 노출하지 않는다. 기존 자식 기록이 있는 세션에서는 남은 변경 요청을 정리할 수 있다.
- Go 임베더의 소스 호환성을 위해 `subagent.DelegateTools()`는 빈 목록을 반환하는 deprecated 함수로 남긴다. 두 이름의 상수는 기존 저장 기록 판독에 사용한다.

## 기존 기록과 실행 제한

기존 세션/자식 ID, 대화, 결과와 변경 요청은 삭제하지 않는다. 이미 저장된 결과는 부모 대화의 미완료 도구 응답을 복구할 때 재사용한다. 저장된 결과가 없으면 티켓 경로 안내로 부모 도구 호출을 마무리하며 새 자식을 만들거나 이전 모델/ACP 실행을 재개하지 않는다. Studio의 예전 위임 트리는 읽기 전용이다.

동시 서브에이전트 실행 수는 프로젝트의 동시 티켓 수와 기존 전역 상한으로 제한한다. 제거된 부모별 Q 직접 위임 제한은 화면에서 제거하며 저장 필드는 이전 설정과의 호환성을 위해 유지한다. ACP 에이전트가 자체적으로 수행하는 내부 도구/하위 에이전트 관리는 해당 ACP에 남아 있다.
