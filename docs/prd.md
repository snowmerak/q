## 1. 배경과 문제

### 1.1 현재 상황과 리셋 배경

- **q v1 (`main`)**은 저장소 단위 코딩 에이전트 및 로컬 제어면으로 출발하여 TUI, Q Studio 웹 UI, Git worktree 기반 위임 코디네이터, 이슈/티켓 칸반, LSP, ACP 브리지, Workspace Memory, Global Library, `llm-provider` 게이트웨이 연동 등으로 기능이 광범위하게 확장되었습니다.
- **Evernight**은 별도 저장소에서 캐릭터·월드 설정, 다중 캐릭터 참여 및 인지 격리(`observedBy`), 개인 기억/가치관/상태·관계 갱신, 단계별 체크포인트 및 Lease 복구 구조를 갖춘 상호작용 엔진을 발전시켜 왔습니다.
- **llm-provider**는 다중 LLM 프로바이더(OpenAI 호환, Anthropic Claude, xAI/Grok, Codex App Server, ChatGPT 로그인 등)를 단일 Go 인터페이스와 OpenAI 호환 게이트웨이로 추상화하고 모델 능력(`capabilities`), 추론 강도, 임베딩, 프롬프트 캐시 정규화를 제공합니다.

### 1.2 해결하려는 문제

q v1은 코딩 IDE 및 다중 에이전트 오케스트레이션 도구의 성격이 강해지면서 일상적인 대화·개인 어시스턴트·캐릭터 상호작용 용도로는 구조와 UI가 무거워졌습니다. 반면 Evernight은 서사·캐릭터 상호작용과 기억·가치관 파이프라인이 강하지만, 사용자의 실질적인 작업(도구 실행, 지식 탐색, 범용 어시스턴트 업무)을 수행하는 봇 구조로 설계되어 있지는 않습니다.

따라서 **q v2**는 v1을 `main` 브랜치와 `v0.5.0` 태그에 보존한 채 `v2` 브랜치에서 코드베이스를 리셋하고, 다음을 목표로 재출발합니다.

- **핵심 정체성:** 사용자와 **캐릭터챗 느낌으로 자연스럽게 상호작용**하는 것을 우선하면서, 필요할 때 **여러 실제 작업(도구 호출, 지식 조회·정리 등)을 수행할 수 있는 봇**.

## 3. 범위 (Scope)

### 3.1 1차 범위 (In-Scope)

1. **캐릭터 및 사용자 페르소나 관리**
   - 캐릭터 프로필(이름, 성격, 배경, 외형, 초기 가치관, 초기 상태/관계, 역할별 모델/추론 설정) 생성·편집.
   - 사용자 페르소나(표시 이름, 외형/설명 등) 설정 및 대화/룸 연결.
2. **1:1 캐릭터 봇 대화**
   - 단일 캐릭터와의 직접 대화, 스트리밍 또는 단계별 진행 상태 표시.
   - 개인 기억·가치관·상태·사용자 관계 유지, 자동 기억 회상, 예산 초과 시 컨텍스트 압축.
   - 실패 요청의 동일 요청 ID 재시도 및 중복 생성 방지.
3. **멀티캐릭터/룸 (Multi-character Room)**
   - 복수 캐릭터가 참여하는 대화방 생성 및 참여자 관리.
   - 캐릭터별 발화/참여 조율, 관찰 범위(`observedBy`) 기반 인지 격리, 비공개 내면/행간 처리.
   - 진행 중 사용자의 실시간 끼어들기(Cut-in) 및 중단(Stop).
4. **대화 연계 작업(Task) 실행**
   - 대화 맥락 안에서 봇이 도구(Tool)를 호출해 작업을 실행하고 결과를 대화로 이어감.
   - 작업 진행 상태(실행 중/완료/실패/취소)와 결과 카드 표시, 대용량 출력의 아티팩트 분리.
5. **지식 저장소 & 장기기억**
   - 대화에서 생성되는 개인/룸 기억, 가치관 변화, 사용자 제공 지식 문서(메모·파일 등)의 저장 및 리비전 관리.
   - 키워드·의미·하이브리드 검색 및 자동 회상 주입.
   - `PostgreSQL / MySQL / SQLite`와 `OpenSearch / Bleve`의 자유로운 조합 지원.
6. **멀티 LLM 프로바이더 및 역할별 모델 선택**
   - `llm-provider`를 통한 다중 프로바이더 연결(로컬 모델 서버, OpenRouter, Anthropic, OpenAI 호환, Codex/ChatGPT 등).
   - 모델별 능력(도구 호출, 컨텍스트 길이, 추론 강도 옵션) 반영 및 역할별 모델 분리(대화, 기억 정리, 회상 플래너, 참여 판단, 임베딩).
7. **UI 및 데스크톱 앱**
   - React + TypeScript + shadcn/ui 기반 UI, 라이트/다크(및 시스템 연동) 모드.
   - Wails v3 기반 데스크톱 앱(로컬 엔진 내장 또는 연동, 창 제어/트레이/백그라운드 유지).

### 3.2 제외 범위 (Out-of-Scope — v2 리셋에서 우선 제외)

1. **q v1의 코딩 IDE/리포지토리 전용 제어면 기능 일체**
   - Git diff 브라우저, worktree 격리 PR/MR 코디네이터, 이슈/티켓 칸반 보드, LSP 코드 인텔리전스, 터미널 TUI, ACP 외부 에이전트 브리지. (추후 필요시 독립 도구나 확장 모듈로 별도 검토)
2. **Evernight의 순수 3인칭 연재 소설 강제 포맷**
   - 대사와 서술을 무조건 3인칭 과거형 소설 본문으로 재집필하는 전용 워크플로. (멀티캐릭터 룸에서 나레이션/소설 스타일을 선택 옵션으로 둘지는 미결 질문에서 다룸)
3. **다중 사용자/외부 공개 SaaS 인증·권한 체계**
   - OAuth 다중 테넌트, 결제/과금, 조직 RBAC 등은 1차 범위에서 제외하며 개인 로컬 또는 신뢰 가능한 네트워크 환경의 셀프호스트를 기준으로 함.
4. **네이티브 모바일 앱 구현 (1차 제외, 추후 검토)**
   - iOS/Android 앱 구현과 스토어 배포는 1차 범위에서 제외하되, 서버 권위 API 및 UI/상태 경계는 추후 모바일 확장을 저해하지 않도록 설계함.

## 4. 대표 사용자 여정 및 요구사항 (`REQ-*`)

### 4.1 대표 사용자 여정

1. **초기 설정 및 캐릭터 준비:** 사용자가 데스크톱 앱을 실행해 저장소 조합(예: 로컬 SQLite + Bleve 또는 PostgreSQL + OpenSearch)과 LLM 프로바이더를 연결하고, 봇 캐릭터와 자신의 페르소나를 만든다.
2. **1:1 대화와 작업 수행:** 사용자가 캐릭터와 일상 대화를 나누다 특정 조사·정리·로컬 작업을 요청하면, 캐릭터는 자신의 말투와 맥락을 유지한 채 도구를 실행하고 진행 상황과 결과를 보여준다.
3. **멀티캐릭터 룸 상호작용:** 사용자가 여러 캐릭터를 한 방에 초대해 대화를 진행하면, 각 캐릭터는 자신이 관찰한 맥락(`observedBy`)과 성격/가치관에 따라 참여·응답하며, 사용자는 언제든 중간에 끼어들거나 흐름을 멈출 수 있다.
4. **기억과 지식 축적:** 대화가 쌓이면 중요한 기억과 캐릭터의 가치관/관계가 백그라운드에서 정리되고, 사용자가 등록한 지식 문서와 함께 다음 대화에서 자동으로 회상되어 활용된다.

### 4.2 기능 및 비기능 요구사항

| ID | 구분 | 요구사항 (주체 · 조건 · 관찰 가능한 동작) | 수용 기준 (Acceptance Criteria) |
| --- | --- | --- | --- |
| `REQ-CHAR-01` | 확정 + 제안 | 사용자는 캐릭터(성격·배경·외형·초기 가치관·초기 상태·모델 설정)와 사용자 페르소나를 생성·수정·삭제할 수 있어야 하며, 새 대화/룸 시작 시 해당 시점의 스냅샷을 세션에 복사해 원본 수정이 진행 중인 대화를 소급 변경하지 않아야 한다. | 1) 캐릭터/페르소나 CRUD 동작.<br>2) 대화 시작 후 원본 캐릭터를 수정해도 기존 대화 세션 스냅샷이 유지됨. |
| `REQ-CHAT-01` | 확정 | 사용자는 선택한 캐릭터와 1:1 대화를 진행하고 스트리밍 또는 단계별 상태를 볼 수 있어야 한다. 네트워크·모델 실패 시 동일 `requestId`로 재시도하면 중복 응답 없이 이어서 완료되거나 복구되어야 한다. | 1) 1:1 메시지 송수신 및 응답 표시.<br>2) 실패 후 동일 `requestId` 재전송 시 중복 턴이 생성되지 않고 체크포인트에서 재개 또는 기존 결과 반환. |
| `REQ-ROOM-01` | 확정 | 사용자는 2명 이상의 캐릭터가 참여하는 룸을 만들고 대화를 진행할 수 있어야 한다. 시스템은 캐릭터별 발화·참여 여부를 조율하고, 각 캐릭터가 볼 수 있는 정보(`observedBy`/장소/비공개 내면)를 격리하며, 사용자의 실시간 끼어들기(Cut-in)와 중단(Stop)을 반영해야 한다. | 1) 복수 캐릭터 참여 룸 생성 및 턴 진행.<br>2) 특정 캐릭터에게 비공개인 정보/다른 위치 사건이 프롬프트에 누출되지 않음.<br>3) 실행 중 중단/끼어들기 요청 시 미확정 추측 단계를 멈추고 사용자 입력을 반영. |
| `REQ-TASK-01` | 확정 + 제안 | 캐릭터(또는 룸 내 지정 봇)는 대화 흐름 중 등록된 도구(작업)를 호출해 작업을 수행할 수 있어야 한다. 시스템은 작업의 실행 상태·도구명·요약 결과를 UI에 구분해 표시하고, 대용량 출력은 아티팩트로 분리해 프롬프트 오염을 방지하며, 사용자 중단 또는 타임아웃 시 안전하게 종료해야 한다. | 1) 대화 중 1개 이상의 도구가 호출되고 결과가 다음 응답에 반영됨.<br>2) UI에서 작업 상태(실행 중/성공/실패/취소)와 대용량 아티팩트 원문을 확인 가능.<br>3) 긴 출력이 전체 대화 컨텍스트를 초과하지 않고 참조 형태로 관리됨. |

## 5. 제약 사항 및 외부 의존성

1. **Go 모듈 및 언어 버전:** `github.com/snowmerak/q/v2` (Go 1.27+ 환경 기준, v1 `go.mod`의 `go 1.27.4` 계승).
2. **참조/통합 자산:**
   - `github.com/snowmerak/llm-provider`: 모델 게이트웨이 및 프로바이더 인터페이스.
   - `github.com/snowmerak/decisions` (선택/판단 계층 연동 여부는 미결 질문 참고).
   - `snowmerak/q` (`main` 브랜치): Loom, 검색/저장소 설정, Wails v3 데스크톱 빌드 패턴 등 선별 이식.
   - `rileyayla/evernight`: `PacedLoop` / `SimpleChatLoop`, `ActorContext`, 기억·가치관·상태/관계 모델, 체크포인트·Lease 패턴 등 선별 이식.
3. **인프라 선택지:**
   - 로컬 최소 구성: `SQLite` + `Bleve` (별도 DB/검색 서버 없이 실행 가능, 단 벡터 검색/임베딩 결합 방식은 청사진 및 ADR에서 확정 필요).
   - 서버/확장 구성: `PostgreSQL` 또는 `MySQL` + `OpenSearch` (외부 프로세스 또는 컨테이너 필요).
   - 임베딩 모델: 로컬 또는 원격 임베딩 API 가용성에 따라 의미 검색이 비활성화될 경우 키워드 검색 폴백 계약이 필요함.
4. **프런트엔드 스택:** React, TypeScript, Tailwind CSS, shadcn/ui.
5. **데스크톱 셸:** Wails v3 (Windows WebView2, macOS WKWebView, Linux GTK4/WebKitGTK 런타임 요구).
