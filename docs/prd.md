# q v2 제품 요구사항 정의서 (PRD)

- **작성일:** 2026-11-28
- **상태:** 1차 구현 및 검증 완료 (`v2` 브랜치 M0~M5 구현 완료)
- **기준 브랜치:** `v2` (`github.com/snowmerak/q/v2`)
- **관련 문서:** [프로젝트 청사진 (Blueprint)](./blueprint.md)
- **대상 독자:** q v2 제품·설계·구현 담당자
- **갱신 조건:** 확정된 제품 범위, 핵심 사용자 여정, 또는 `REQ-*` 요구사항을 변경할 때 갱신한다.

> [!NOTE]
> 이 문서는 제품 문제, 확정 범위, 사용자 여정 및 요구사항을 다룹니다. 구체적인 `pkg/` 패키지 구조, 저장소 포트/어댑터 계약, 실행 시퀀스, 기술 리스크 및 세부 ADR은 [프로젝트 청사진 (Blueprint)](./blueprint.md)에 둡니다.

## 1. 배경과 문제

### 1.1 현재 상황과 리셋 배경

- **q v1 (`main`)**은 저장소 단위 코딩 에이전트 및 로컬 제어면으로 출발하여 TUI, Q Studio 웹 UI, Git worktree 기반 위임 코디네이터, 이슈/티켓 칸반, LSP, ACP 브리지, Workspace Memory, Global Library 등으로 기능이 광범위하게 확장되었습니다.
- **Evernight**은 별도 저장소에서 캐릭터·월드 설정, 다중 캐릭터 참여 및 인지 격리(`observedBy`), 개인 기억/가치관/상태·관계 갱신, Decisions 기반 이산 판단, 단계별 체크포인트 복구 구조를 갖춘 상호작용 엔진을 발전시켜 왔습니다.
- **llm-provider**는 다중 LLM 프로바이더를 단일 Go 인터페이스와 OpenAI 호환 게이트웨이로 추상화하고 모델 능력(`capabilities`), 추론 강도, 임베딩, 프롬프트 캐시 정규화를 제공합니다.
- **cdp-q-driver**는 Chrome/Chromium CDP 기반 브라우저 자동화 라이브러리와 CLI를 제공합니다.

### 1.2 해결하려는 문제

q v1은 코딩 IDE 및 다중 에이전트 오케스트레이션 도구의 성격이 강해지면서 일상적인 대화·개인 어시스턴트·캐릭터 상호작용 용도로는 구조와 UI가 무거워졌습니다. 또한 다중 프로세스 동시 실행·분산 락 전제와 루트에 분산된 다수 패키지 구조가 유지보수 부담을 키웠습니다. 반면 Evernight은 캐릭터 상호작용과 기억·가치관 파이프라인이 강하지만, 3인칭 연재 소설 집필 중심이라 사용자의 실질적인 작업(파일/셸/지식/MCP/브라우저/위임)을 수행하는 봇 구조로 설계되어 있지는 않습니다.

따라서 **q v2**는 v1을 `main` 브랜치와 `v0.5.0` 태그에 보존한 채 `v2` 브랜치에서 코드베이스를 리셋하고(기존 데이터 비이관·클린 스타트), 다음을 목표로 재출발합니다.

- **핵심 정체성:** 단일 인스턴스(Single-instance) 코어 엔진 위에서 사용자와 **채팅 버블 중심의 캐릭터챗 감각으로 상호작용**하는 것을 우선하면서, 필요할 때 **여러 실제 작업(파일/셸·지식/아카이브·Loom·스킬·MCP·브라우저·위임 등)을 수행할 수 있는 봇** (Server CLI와 Wails v3 데스크톱 앱이 동일 코어 로직을 공유하고, `llm-provider`와 `cdp-q-driver`는 공개 라이브러리·독립 CLI로 함께 통합 제공).

## 3. 범위 (Scope)

### 3.1 1차 범위 (In-Scope)

1. **캐릭터 및 사용자 페르소나 관리**
   - 캐릭터 프로필(이름, 성격, 배경, 외형, 초기 가치관, 초기 상태/관계, 역할별 모델/추론 설정) 생성·편집.
   - 사용자 페르소나(표시 이름, 외형/설명 등) 설정 및 대화/룸 연결.
2. **1:1 캐릭터 봇 대화**
   - 단일 캐릭터와의 직접 채팅 버블 대화, 스트리밍 또는 단계별 진행 상태 표시.
   - 개인 기억·가치관·상태·사용자 관계 유지, Decisions 기반 자동 기억 회상, 예산 초과 시 컨텍스트 압축.
   - 실패 요청의 동일 요청 ID 재시도 및 중복 생성 방지.
3. **멀티캐릭터/룸 (Multi-character Room)**
   - 복수 캐릭터가 참여하는 대화방 생성 및 참여자 관리.
   - 산문 재작성 없는 **채팅 버블 중심** 직접 대화.
   - **Decisions** 기반 캐릭터별 발화/참여 조율, 관찰 범위(`observedBy`) 기반 인지 격리, 비공개 내면/행간 처리.
   - 진행 중 사용자의 실시간 끼어들기(Cut-in) 및 중단(Stop).
4. **대화 연계 작업(Task) 실행 및 승인 게이트**
   - 1차 내장 도구 범위 (Q v1 기준 IDE/Git/티켓 전용 도구를 제외한 7개 영역):
     1. **파일·디렉터리 작업:** `read_file`, `edit_file`, `write_file`, `list_directory`, `create_directory`, `move_path`, `copy_path`, `remove_path`
     2. **셸·커맨드 실행:** `run_command`, `cmd_status`, `wait`
     3. **아카이브·기억/지식 조회:** `search_archive`, `get_archive_record`
     4. **Loom 아티팩트:** `loom_inspect`, `loom_read`, `loom_eval`
     5. **Agent Skills:** `search_skills`, `get_skill`
     6. **외부 확장 & 브라우저:** 외부 MCP 서버 도구 연동 + `browser_control` config 기반 브라우저 드라이버 선택(`cdp-q-driver` / `ego-browser`)
     7. **오케스트레이션·상호작용:** `ask_to_user`(확인 질문) 및 서브에이전트/작업 위임(`task_start`, `task_complete`, `delegate_*` 등)
   - 3단계 승인 게이트 모드 지원:
     - `bypass`: 승인 없이 무조건 실행
     - `auto-detection`: Decisions로 체크해 승인이 필요한 호출만 사용자에게 승인 요청
     - `request`: 모든 도구 호출에 대해 사용자 승인 요청
   - 작업 진행 상태(실행 중/승인 대기/완료/실패/취소)와 결과 카드 표시, 대용량 출력의 Loom 아티팩트 분리.
5. **지식 저장소 & 장기기억 & 전역 데이터 관리**
   - 대화에서 생성되는 개인/룸 기억, 가치관 변화, 사용자 제공 지식 문서(메모·파일 등)의 저장 및 리비전 관리.
   - 키워드·의미(벡터)·하이브리드 검색 및 자동 회상 주입.
   - `PostgreSQL / MySQL / SQLite`와 `OpenSearch / Bleve + HNSW`의 자유로운 조합 지원.
   - 단일 전역 데이터 디렉터리(기본 경로 + `--data-dir` 오버라이드)에 설정·데이터·블롭 일원화.
6. **통합 `llm-provider` · `cdp-q-driver` · `decisions` 연동**
   - 레포 내 통합된 `pkg/llm`(`llm-provider`)을 코어 엔진에 직접 임베드해 사용하며 외부 게이트웨이 URL 연결도 허용.
   - `pkg/llm`과 `pkg/cdp`(`cdp-q-driver`)를 공개 Go 라이브러리로 유지하고, 별도 독립 CLI(`cmd/llm-provider`, `cmd/cdp-q-driver`) 제공.
   - `decisions`(`github.com/snowmerak/decisions`)를 통한 이산 판단(참여, 기억 회상 게이트/선별, 승인 게이트 `auto-detection` 등) 수행.
7. **공유 코어 기반 웹 UI 및 데스크톱 앱**
   - React + TypeScript + shadcn/ui 기반 웹 UI, 라이트/다크(및 시스템 연동) 모드. (`web/dist`는 Git에 커밋하지 않고 빌드/릴리스 시 생성해 Go 바이너리에 임베드)
   - Wails v3 데스크톱 앱과 `cmd/q`(Server/CLI)가 동일한 코어 Go 패키지를 공유해 동작.

### 3.2 제외 범위 (Out-of-Scope — v2 리셋에서 확정 제외)

1. **q v1의 코딩 IDE/리포지토리 전용 제어면 기능 일체**
   - Git diff 브라우저, worktree 격리 PR/MR 코디네이터(`change_request_read`, `review_task`, `ticket_question` 등), 이슈/티켓 칸반 보드, LSP 도구(`lsp_*` 7종), 터미널 TUI, ACP 외부 에이전트 브리지.
2. **Evernight의 3인칭 산문·연재 소설 재집필 파이프라인**
   - 캐릭터 발화·행동을 모아서 3인칭 과거형 소설 본문(`prose`)으로 다시 쓰는 워크플로 및 문체 프리셋은 v2에서 제외하고 채팅 버블 중심으로 단순화함.
3. **다중 프로세스 동시 실행 및 분산 리더 선출/멀티노드 락 오케스트레이션**
   - q v1의 다중 프로세스 리더 선출/팔로워 프록시(`workspace-memory`, `library`)나 다중 코어 인스턴스 간 분산 락을 지원하지 않고, 단일 인스턴스(Single-instance) 코어 엔진 실행을 전제로 함.
4. **기존 데이터 이관 (Legacy Migration 제외)**
   - Evernight(PostgreSQL/OpenSearch/JSON) 및 Q v1의 기존 세션·지식·설정 데이터는 이관하거나 변환 도구를 제공하지 않으며, v2는 신규 데이터로 깨끗하게 시작함.
5. **모바일 앱 및 모바일 전용 대응 제외**
   - iOS/Android 네이티브 앱, 모바일 PWA 및 모바일 전용 UI 확장은 v2 범위에서 제외하며 Desktop(Wails v3)과 웹 브라우저 UI에 집중함.
6. **다중 사용자/외부 공개 SaaS 인증·권한 체계**
   - OAuth 다중 테넌트, 결제/과금, 조직 RBAC 등은 제외하며 개인 로컬 또는 신뢰 가능한 네트워크 환경의 단일 사용자 운용을 기준으로 함.

## 4. 대표 사용자 여정 및 요구사항 (`REQ-*`)

### 4.1 대표 사용자 여정

1. **초기 설정 및 캐릭터 준비:** 사용자가 Wails v3 데스크톱 앱(또는 `cmd/q`)을 실행해 단일 전역 데이터 디렉터리(`--data-dir` 변경 가능)에 저장소 조합, LLM 프로바이더(`pkg/llm`), Decisions 모델, `browser_control`(`cdp-q-driver` / `ego-browser`), 도구 승인 게이트 기본 모드를 설정하고 캐릭터와 페르소나를 만든다.
2. **1:1 대화와 작업 수행:** 사용자가 캐릭터와 대화를 나누다 파일/셸·지식/아카이브·스킬·MCP·브라우저·서브에이전트 작업을 요청하면, 설정된 승인 게이트(`bypass` / `auto-detection` / `request`)에 따라 즉시 실행하거나 사용자 승인/`ask_to_user` 확인을 거친 뒤 결과를 채팅 버블과 작업 카드로 보여준다.
3. **멀티캐릭터 룸 상호작용:** 사용자가 여러 캐릭터를 한 방에 초대해 대화를 진행하면, Decisions가 참여/발화 순서를 조율하고 각 캐릭터는 자신이 관찰한 맥락(`observedBy`)과 성격/가치관에 따라 채팅 버블로 응답하며, 사용자는 언제든 중간에 끼어들거나 흐름을 멈출 수 있다.
4. **기억과 지식 축적:** 대화가 쌓이면 중요한 기억과 캐릭터의 가치관/관계가 백그라운드에서 정리되고, 사용자가 등록한 지식 문서와 함께 다음 대화에서 자동으로 회상되어 활용된다.

### 4.2 기능 및 비기능 요구사항

## 5. 제약 사항 및 외부 의존성

1. **Go 모듈 및 실행 모델:** `github.com/snowmerak/q/v2` (Go 1.27+ 환경 기준, `go 1.27.4`), **단일 인스턴스(Single-instance)** 코어 엔진 프로세스 전제.
2. **레포 내 통합 자산 (공개 라이브러리 + 독립 CLI):**
   - `llm-provider` → `pkg/llm` + `cmd/llm-provider`로 직접 통합.
   - `cdp-q-driver` → `pkg/cdp` + `cmd/cdp-q-driver`로 직접 통합.
3. **참조/외부 자산:**
   - `github.com/snowmerak/decisions`: 참여/회상/도구 승인 판단 등 이산 판단 계층.
   - `ego-browser`: `browser_control` config에서 선택 가능한 외부 브라우저 CLI 드라이버 옵션.
   - `snowmerak/q` (`main` 브랜치): Bleve+HNSW 검색 결합, 내장 도구(파일·셸·Loom·Skills·위임 패턴), `storageconfig`, `browser_control` 설정 구조, Wails v3 데스크톱 빌드 경험 선별 이식.
   - `rileyayla/evernight`: `SimpleChatLoop` / `PacedLoop` 스케줄링·`observedBy`·`InterceptHub`·기억/가치관/상태·체크포인트 복구 패턴 선별 이식.
4. **인프라 및 데이터 경로 선택지:**
   - 로컬 최소 구성: `SQLite` + `Bleve + HNSW` (별도 DB/검색 서버 없이 단일 프로세스 내 실행 가능).
   - 서버/확장 구성: `PostgreSQL` 또는 `MySQL` + `OpenSearch`.
   - 데이터 저장 위치: 단일 전역 데이터 디렉터리(기본값) + `--data-dir` 오버라이드 (기존 데이터 비이관).
5. **빌드 및 UI 스택:**
   - React, TypeScript, Tailwind CSS, shadcn/ui. (`web/dist`는 `.gitignore`로 제외하며, 소스 빌드/릴리스 시 Node/pnpm 환경이 필요함)
   - Wails v3 (`desktop/` 별도 Go 모듈; Windows WebView2, macOS WKWebView, Linux GTK4/WebKitGTK 런타임 요구).
