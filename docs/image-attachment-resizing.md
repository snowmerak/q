# 이미지 첨부 리사이징

Q는 새 첨부 이미지의 전체 영역과 종횡비를 유지하며, 전송 한도를 넘는 이미지를 축소한다. Studio에서 이미지를 첨부하면 입력창의 **Image resolution**에서 이번 메시지에 적용할 크기를 고를 수 있다.

| 설정 | 긴 변 상한 | 32×32 패치 상한 |
| --- | ---: | ---: |
| **Standard · 2,048 px** | 2,048px | 2,500개 |
| **Smaller · 1,600 px** | 1,600px | 2,500개 |

두 한도를 만족하는 가장 큰 크기로 축소하며, 한도에 들어오는 이미지는 원본 바이트로 보낸다. 예를 들어 `3420×1312` 이미지는 Standard에서 `2048×786`이 된다. 정사각형 `2048×2048` 이미지는 패치 한도로 인해 `1600×1600`이 된다. `1888×1056` 이미지에 Smaller를 선택하면 `1600×895`가 된다.

Studio 메시지 API와 Go `SessionOptions`는 각각 `image_max_edge`와 `ImageMaxEdge`로 크기를 받는다. `1600`은 Smaller를, `2048` 또는 생략한 값은 Standard를 적용한다. 새 티켓 첨부와 Q가 받는 PNG·JPEG·GIF·WebP ACP 이미지에도 Standard를 적용한다.

## 컨텍스트와 저장

Q는 새 이미지를 준비한 뒤 모델 요청 메시지에 넣는다. 전송 전 85% 압축 판정은 이 이미지의 해상도로 추정한다. 응답 후에는 공급자가 보고한 전체 입력 토큰으로 사용량 기준을 갱신한다. 공급자마다 이미지 토큰 계산이 달라 해상도 감소에 따른 실제 절감 폭도 다를 수 있다.

Studio 대화에는 모델에 전송한 이미지를 저장한다. 티켓 원본 파일은 그대로 참조할 수 있고, ACP는 대화 재생에 필요한 원본 블록을 유지한다. 리사이징은 새 첨부를 준비하는 시점에 적용된다.

## 파일 크기와 형식

Studio에 올리는 원본은 최대 4장, 장당 4 MiB, 합계 8 MiB다. 축소본이 이 바이트 한도를 넘으면 해상도를 더 낮춘다. 축소하는 JPEG는 JPEG로 인코딩하고, PNG·GIF·WebP는 PNG로 인코딩한다. 축소하는 GIF는 첫 프레임을 사용한다. 입력 파일을 디코딩할 수 없거나 로컬 디코딩 한도인 4천만 픽셀 또는 긴 변 16,384px를 넘으면 오류를 표시한다.
