## 계획 시작

작업에 요구사항 명확화, 명시적 승인, 검토되는 작업 분할, 중단 후 복구가 필요하면 `/plan`을 사용하세요.

```text
/plan 현재 캐시를 크기가 제한된 LRU 구현으로 교체해줘
```

일반 채팅 요청도 도구를 직접 사용할 수 있으며 자동으로 계획 워크플로에 들어가지는 않습니다.

비대화형 호출에서는 프로세스 단위 자동화를 켠 같은 워크플로를 실행할 수 있습니다.

```powershell
q sprint 현재 캐시를 크기가 제한된 LRU 구현으로 교체해줘
```

## 워크플로 역할

기본 경로는 다음과 같습니다.

1. **Griller**는 저장소 증거로 답할 수 없는 결정만 질문합니다.
2. **Scout**는 필요한 경우 범위가 제한된 비변경 조사를 수행합니다.
3. **Planner**는 작업, 대상, 실행자, 완료 기준, 검증 방법을 제안합니다.
4. **Executor**는 승인된 작업을 Coder 또는 구성된 외부 실행자로 수행합니다.
5. **Planner 검토**는 결과를 승인하거나 제한된 재시도 피드백을 보냅니다.

작업은 순차적으로 실행되며 제한된 시도 횟수를 공유합니다. 실행이 중단되어도 이미 바뀐 파일은 자동으로 되돌아가지 않습니다.

## 자동화 제어

`/auto-resolve`는 q가 엔지니어링 기본값으로 계획 질문에 답할지를 제어합니다. `/auto-approve`는 유효한 Planner 제안을 자동 승인할지를 제어하며, `/autonomous`는 두 설정을 함께 바꿉니다.

```text
/auto-resolve on
/auto-approve on
/autonomous status
```

자동화는 제안 검증, 작업 실행, Planner 검토를 건너뛰지 않습니다.

## 중단 후 재개

활성 실행은 선택된 세션 아래에 체크포인트로 저장됩니다.

```text
.q/sessions/<uuid>/plan-execution.json
```

다시 시작하면 Resume, Inspect, Discard 중에서 선택할 수 있습니다. Discard는 체크포인트를 제거하지만 실행자가 이미 바꾼 파일을 되돌리지는 않습니다.
