## 저장소 변경 검토

`/changes`를 실행해 q의 읽기 전용 Git 브라우저를 엽니다. 현재 저장소의 스테이징된 파일, 스테이징되지 않은 파일, 추적되지 않은 파일을 보여줍니다.

- 위/아래 또는 `j`/`k`로 파일을 선택합니다.
- Enter로 diff에 초점을 맞추고 Tab으로 파일과 diff 패널을 전환합니다.
- PageUp/PageDown으로 세로 스크롤하고 왼쪽/오른쪽으로 긴 줄을 이동합니다.
- `r`은 저장소 상태를 다시 불러오며 Escape는 채팅으로 돌아갑니다.

이 화면을 여는 것만으로 파일을 스테이징, 수정, 커밋하지는 않습니다.

## 화면 이해

브라우저는 현재 q 턴 이전에 존재한 변경을 포함한 저장소 전체 상태를 표시합니다. 에이전트 턴별 감사 로그가 아닙니다.

스테이징 및 비스테이징 패치는 `HEAD` 기준으로 서로 상쇄되더라도 따로 표시됩니다. 알려진 텍스트 형식은 구문 강조를 사용하고 바이너리는 안내를 표시합니다. 알 수 없거나 너무 큰 소스는 일반 텍스트로 표시합니다. 선택한 미리보기는 256 KiB 또는 4,000줄로 제한되며 일부만 표시할 때 이를 알립니다.

## 커밋 준비

채팅에서 `/commit`을 실행하거나 현재 저장소에서 독립 워크플로를 시작하세요.

```powershell
q commit
```

스테이징된 변경이 있으면 q는 현재 인덱스를 사용합니다. 인덱스가 비어 있으면 q 소유 루트 `.q` 메타데이터를 제외하고 현재 작업 트리 변경을 스테이징합니다. 그런 다음 구성된 `commit` 모델에 하나의 Conventional Commit 메시지 또는 분할 커밋 제안을 요청합니다.

커밋을 만들기 전에 q는 캡처한 인덱스가 제안과 여전히 일치하는지 확인합니다. 검토 중 저장소 상태가 바뀌었다면 오래된 그룹을 커밋하지 말고 다시 생성하거나 워크플로를 다시 시작하세요.

## 검토와 완료

커밋 화면에서 위/아래로 분할 제안을 선택하고 `e`로 메시지를 편집하며 `Ctrl+S`로 저장합니다. `r`은 제안을 다시 생성합니다. Enter는 승인된 제안을 커밋하고, `p`는 커밋 후 푸시합니다. 푸시하려면 기존 upstream이 있어야 합니다. Escape는 커밋 없이 취소합니다.

승인 전에 각 분할의 파일과 메시지를 확인하세요. q는 Git 작업을 제안하고 실행할 수 있지만 현재 작업과 무관한 기존 변경까지 소유한다고 가정하지 않습니다.
