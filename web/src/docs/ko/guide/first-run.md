## Studio 시작

내장 로컬 웹 애플리케이션을 시작하세요. 어느 디렉터리에서 실행하더라도 여러 저장소의 세션을 관리할 수 있습니다.

```powershell
q studio
```

Studio는 루프백 URL을 출력하고 브라우저에서 엽니다. 인터페이스를 사용하는 동안 해당 q 프로세스를 계속 실행해 두세요.

## 모델 구성

**Settings → Providers**에서 Gateway 공급자를 추가하고 endpoint와 API 키 환경변수를 입력하세요. 그다음 **Settings → Models**에서 검색된 모델을 **Default**에 할당합니다. 공급자와 모델 변경은 자동 저장됩니다.

Agent Skill 적합성 검사처럼 별도의 typed decision 공급자를 사용할 때만 **Settings → System One**을 구성하면 됩니다.

## 세션 생성

**Sessions**에서 **Add session**을 선택하세요. 폴더 탐색기로 저장소 디렉터리를 고른 뒤 기존 루트 세션을 선택하거나 새 세션을 만듭니다. Studio는 해당 루트 세션의 저장소 위치를 기억합니다.

Studio를 저장소 하위 디렉터리에서 실행해도 파일 경계가 자동으로 넓어지지 않습니다. 각 세션은 등록할 때 지정한 정확한 워크스페이스 디렉터리에서 실행됩니다.

## 첫 요청 보내기

q가 증거를 수집하는 방식을 확인할 수 있도록 구체적인 저장소 질문으로 시작하세요.

```text
이 프로젝트가 시작되는 경로와 주요 런타임 구성 요소를 설명해줘.
```

전문 역할이 필요한 변경이라면 메인 에이전트에게 위임을 요청하거나 직업형 역할을 직접 지정할 수 있습니다.

```text
시니어 개발자에게 상태 확인 엔드포인트 추가와 검증을 맡겨줘.
```

자식 에이전트는 세션 트리에서 부모 아래에 나타납니다. 자식을 선택하면 별도의 대화와 도구 활동을 확인할 수 있습니다.

## 결과 검토

**Changes**에서 스테이징, 비스테이징, 이름 변경과 미추적 파일을 살펴보세요. 파일을 선택하면 구문 강조된 diff를 볼 수 있습니다.

diff가 준비되면 커밋 검토를 시작해 Conventional Commit 또는 분할 커밋 제안을 생성합니다. 선택한 제안을 실행하기 전에는 커밋되지 않습니다.
