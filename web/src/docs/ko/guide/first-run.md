## 워크스페이스 열기

q가 작업할 프로젝트 디렉터리에서 시작하세요. 활성 워크스페이스는 파일 도구, 검색, 세션 저장소, 워크스페이스 지침, 스킬, 모델 오버라이드의 기준이 됩니다.

```powershell
cd C:\work\my-project
q
```

저장소 하위 디렉터리에서 시작해도 파일 도구 경계가 Git 루트까지 자동 확장되지는 않습니다. 다만 저장소 수준의 휴대 가능한 Agent Skills는 가장 가까운 Git 루트에서 찾을 수 있습니다.

## 모델 구성

첫 실행에서는 공급자 설정이 열립니다. 공급자를 추가하고 모델을 선택한 뒤 기본 역할에 할당하세요. 공급자 API 키를 직접 저장하기보다는 환경변수를 사용하는 것이 좋습니다.

언제든 `/model`로 모델 할당을, `/gateway`로 공급자 구성을 다시 열 수 있습니다.

## 첫 요청 보내기

q가 증거를 수집하는 방식을 확인할 수 있도록 구체적인 저장소 질문으로 시작하세요.

```text
이 프로젝트가 시작되는 경로와 주요 런타임 구성 요소를 설명해줘.
```

승인된 계획이 필요한 변경이라면 다음처럼 사용합니다.

```text
/plan 상태 확인 엔드포인트를 추가하고 테스트도 작성해줘
```

`Ctrl+C`는 활성 턴을 중단합니다. `Ctrl+H`는 현재 화면 상태를 유지한 채 전체 키 도움말을 엽니다.

## 결과 검토

`/changes`를 실행해 스테이징된 파일, 스테이징되지 않은 파일, 추적되지 않은 파일을 살펴보세요. 이 화면은 현재 턴 이전에 존재하던 변경을 포함한 저장소 전체 상태입니다.

diff가 준비되면 `/commit`이 Conventional Commit 또는 분할 커밋 제안을 생성합니다. 검토 화면에서 확인하기 전에는 커밋되지 않습니다.
