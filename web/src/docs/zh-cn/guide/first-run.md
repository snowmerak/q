## 打开工作区

在希望 q 操作的项目目录中启动。当前工作区决定文件工具、发现范围、会话存储、工作区指令、技能和模型覆盖的边界。

```powershell
cd C:\work\my-project
q
```

从仓库子目录启动时，文件工具边界不会自动扩展到 Git 根目录。不过，仍可以从最近的 Git 根目录发现仓库级的便携式 Agent Skills。

## 配置模型

首次启动会打开提供商设置。添加提供商、选择模型并将其分配给默认角色。建议通过环境变量提供 API 密钥，而不是直接存储凭据。

可以随时通过 `/model` 重新打开模型分配，通过 `/gateway` 重新打开提供商设置。

## 发送第一个请求

先提出一个具体的仓库问题，以观察 q 如何收集证据：

```text
解释这个项目如何启动，并指出主要的运行时组件。
```

对于需要审批计划的修改，可以输入：

```text
/plan 添加健康检查端点并编写测试
```

`Ctrl+C` 中断当前轮次。`Ctrl+H` 会在保留当前屏幕状态的情况下打开完整的按键参考。

## 审查结果

运行 `/changes` 查看已暂存、未暂存和未跟踪的仓库变更。该视图代表整个仓库，也包含本轮工作之前已有的变更。

diff 就绪后，`/commit` 会生成 Conventional Commit 或拆分提交方案。只有在审查界面确认后才会创建提交。
