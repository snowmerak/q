## Studio を起動

組み込みのローカル Web アプリを起動します。起動したディレクトリに関係なく、任意のリポジトリのセッションを管理できます。

```powershell
q studio
```

Studio はループバック URL を表示してブラウザで開きます。インターフェースを使う間は q プロセスを実行したままにしてください。

## モデルを設定

**Settings → Providers** で Gateway プロバイダーを追加し、endpoint と API キー環境変数を入力します。次に **Settings → Models** で検出されたモデルを **Default** に割り当てます。変更は自動保存されます。

Agent Skill の適合性確認などに独立した typed decision プロバイダーを使う場合だけ、**Settings → System One** を設定します。

## セッションを作成

**Sessions** で **Add session** を選びます。フォルダーブラウザーからリポジトリを選び、既存のルートセッションを登録するか新規作成します。Studio はルートセッションごとにリポジトリ位置を記憶します。

各セッションは登録時に指定した正確なワークスペースディレクトリで実行されます。

## 最初の依頼

まず、q が根拠を集める流れを確認できる具体的な質問を送ります。

```text
このプロジェクトの起動経路と主要なランタイム構成要素を説明して。
```

専門的な作業では、メインエージェントに委任を依頼するか、職種型ロールを指定します。子エージェントはセッションツリーの親の下に表示され、選択すると専用の会話とツール操作を確認できます。

## 結果をレビュー

**Changes** でステージ済み、未ステージ、名前変更、未追跡ファイルとハイライト diff を確認します。準備ができたらコミットレビューを開始し、Conventional Commit または分割コミット案を生成します。選択した案を実行するまでコミットされません。
